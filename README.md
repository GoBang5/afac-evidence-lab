# Upstream: AFAC2026-4 Financial Long-Document QA Agent

This repository implements an evidence-first Agent for the AFAC2026-4 financial long-document multiple-choice task.

The core design follows `answering_strategy.md`: restrict document scope, parse the question, retrieve evidence per option, pack the minimum sufficient evidence, judge A/B/C/D independently, normalize the answer, verify risk flags, and write reproducible outputs.

## Current Runtime

- Python: 3.12+ recommended.
- Agent V0 uses Python standard-library modules only.
- `requirements.txt` is intentionally minimal.
- Preprocessing data under `processed_data/` is generated by the earlier MinerU/DocPreprocess pipeline and is not tracked by Git.

## Compliance Boundary

- Official answering must use deterministic rules and/or Qwen series models only.
- Embedding retrieval is not used.
- Qwen calls are blocked unless `--allow-qwen` is passed explicitly.
- `prior_csv` mode is only for continuity/debugging. It imports existing draft answers and must not be treated as a fresh official judgement.
- GLM/openai-compatible modes are development/evaluation modes unless a competition rule explicitly permits them for the target run.

## Main Entry

```bash
python script/11_run_agent_v0.py \
  --judge-mode none \

  --output-dir runs/smoke_none \

```

## Reproduce Current Group A Prior Run

This run does not call any model. It validates retrieval, evidence packing, answer normalization, verifier, repair, and output writing.

```bash
python script/11_run_agent_v0.py \
  --run-id group_a_prior_repair_v2 \
  --output-dir runs/group_a_prior_repair_v2 \
  --judge-mode prior_csv \
  --prior-answers-csv processed_data/agent_evidence_seed/group_a_all_agent_answers_second_pass.csv
```

Expected shape:

- 100 question rows.
- 68/68 Group A docs covered by selector plus raw fallback.
- Outputs:
  - `answer.csv`
  - `evidence.json`
  - `questions.jsonl`
  - `needs_review.jsonl`
  - `summary.json`

## Audit Run Outputs

Strict audit mode is intended for official-style outputs. It fails if the run still contains development-only priors or unresolved review flags.

```bash
python script/12_audit_agent_outputs.py \
  --run-dir runs/group_a_prior_repair_v2
```

Development audit mode allows the known `prior_csv` and `needs_review` risks while still checking CSV schema, answer legality, qid coverage, token totals, evidence ids, and judgement shape.

```bash
python script/12_audit_agent_outputs.py \
  --run-dir runs/group_a_prior_repair_v2 \
  --allow-needs-review \
  --allow-prior-csv
```

For the current prior run, development audit passes and writes:

- `runs/group_a_prior_repair_v2/audit_report.json`
- `runs/group_a_prior_repair_v2/audit_report.md`

## Model Judge Configuration

The model judge uses an OpenAI-compatible `/chat/completions` API and strict JSON prompts.

Development GLM-style run:

```bash
python script/11_run_agent_v0.py \
  --judge-mode glm \
  --env-file /public/home/zhangfanjin/zhangnianhao/.env \
  --qid reg_a_001 \
  --run-id glm_smoke \
  --output-dir runs/glm_smoke
```

GLM defaults use `GLM_API_KEY`, `GLM_API_URL`, and model `GLM-5V-Turbo` when no explicit `--llm-model` is provided.

Partial smoke runs can be audited with:

```bash
python script/12_audit_agent_outputs.py \
  --run-dir runs/glm_smoke \
  --allow-partial
```

Official Qwen-style run requires explicit authorization:

```bash
python script/11_run_agent_v0.py \
  --judge-mode qwen \
  --allow-qwen \
  --env-file /public/home/zhangfanjin/zhangnianhao/.env \
  --llm-model qwen3.6-plus \
  --qid reg_a_001 \
  --run-id qwen_smoke \
  --output-dir runs/qwen_smoke
```

Do not run the Qwen command until the user has explicitly authorized Qwen API usage for the official chain.

## Agent Package

- `agent/schema.py`: run, question, evidence, judge, and result dataclasses.
- `agent/text.py`: lexical normalization and number/year/clause extraction.
- `agent/domain_rules.py`: domain playbooks and question-feature extraction.
- `agent/retrieval.py`: deterministic lexical/rule retrieval with raw fallback for non-PDF docs.
- `agent/packer.py`: compact evidence packing with stable `evidence_id`.
- `agent/judge.py`: no-model, prior CSV, and model judge modes.
- `agent/prompting.py`: strict JSON model prompt.
- `agent/verify.py`: answer normalization and local audit flags.
- `agent/repair.py`: one-round supplementary retrieval.
- `agent/runner.py`: end-to-end orchestration and output writing.
