# 真实模型泛化与消融试验｜2026-09-30

已读取项目约定的本地配置，实际调用 `ecnu-plus`，服务返回模型标识为 `qwen3.8-27b`。本轮补充了 **60 题、四组条件、208 次真实请求**。完整检索组的直接答案匹配为 **26/60（43.33%）**。

这是公开 FinQA 测试集上的分层小样本试验，不是此前 1,147 题全部经过模型答题，也不是 FinQA 官方程序执行准确率。既有离线报告中的“0次调用”仅描述当时的实验；本报告记录新增真实调用。

## 协议

固定使用纯文本、纯表格、混合证据各20题，涉及37家公司；在各层内按 `SHA256(20260930-model-v1:qid)` 排序取前20题，选择发生在本轮API结果产生前。未按正确率筛题或修改提示词。原公开测试集三层大小为283、706、158，均衡样本刻意增加混合证据题比重。

四组使用同一模型、温度0、关闭思考模式、JSON输出、最大输出512 tokens、最多20,000输入字符；串行调用，无自动重试。两个检索组使用上轮固定的top-5结果，均不读取答案或标注证据。无检索组只给题目；标注证据组使用 `gold_inds` 指定的原文事实，只作取证诊断，不计为端到端检索表现。所有组都要求只依据提供的材料作答，证据不足则返回null。

相同消息、模型和参数的请求按哈希复用一次真实响应，因此240条条件记录对应208次请求，减少了32次重复调用。它们不是独立的重复采样。API凭证仅用于本地请求头，不进入提示词、命令参数或报告。

## 答案匹配与消融

采用预先固定的直接答案评分：百分号字符串转小数；数值四舍五入到5位小数后与 `exe_ans` 精确比较，yes/no忽略大小写比较；空答、格式失败、请求失败、输出截断均按错误计入分母。不尝试根据正确答案猜测100倍缩放，也不在看到结果后调整容差。请求提示词已明确百分比用小数表示。

这借鉴了[官方执行器的数值舍入口径](https://github.com/czyssrs/FinQA/blob/0f16e2867befa6840783e58be38c9efb9229d742/code/evaluate/evaluate.py)，但本轮模型直接输出答案，未生成/执行FinQA程序，因此名称为“直接答案匹配”，不能写成官方execution accuracy。

## 错误诊断

标注证据组仍有27题未匹配，其中9题拒答，说明只补齐标注事实尚不足以解决回答问题。抽查发现明确的算术/输出一致性错误：`BKR/2017/page_56.pdf-4`返回算式`262 + (-472) + (-102)`，但答案字段给出457，正确计算为−312；`GPN/2018/page_94.pdf-1`的算式为`1226 × 78.29`，答案写成95979.54，正确值为95983.54。这些是事后错误诊断，没有用来修改本轮答案或提示词。

也有严格精度失败，例如`L/2009/page_84.pdf-2`输出−0.37而参考值为−0.37001，按预定5位小数规则计错。后续可在开发集引入受控计算器、算式与答案一致性检查，再进行独立评测；本轮没有事后放宽评分或把计算器修正值替换模型输出。
